# Мониторинг LOTOS

Монитор проверяет CRM live, готовность PostgreSQL через CRM, HTML страницы CRM, Parent health, публичный каталог Parent и свежесть резервной копии. Проверки идут из сети GitHub Actions с обычным DNS. Доступность из сетей тренеров проверяется отдельно.

## Запуск и результаты

- Workflow **Operations monitor** запускается каждые 5 минут при `OPS_MONITOR_ENABLED=true` и вручную через **Run workflow** на ветке `main`.
- Расписание GitHub Actions работает best effort, без гарантированного интервала.
- Два последовательных неуспешных прогона открывают инцидент и завершают workflow с ошибкой. Успешная проверка закрывает инцидент.
- Ответ дольше 5 секунд считается деградацией. Проверяется также формат JSON и тип HTML, перенаправления не принимаются.
- Предыдущее состояние читается из артефактов завершённых запусков этого workflow. Новый `operations-state` сохраняется даже при ошибке и хранится 7 дней.
- Результаты доступны в GitHub Actions: статус запуска, журнал проверок и `operations-state`. SMTP и служебные письма удалены 11.11.2026. Настройки `OPS_SMTP_*` и `OPS_EMAIL_TO` больше не используются; старые почтовые поля состояния очищаются при следующем запуске.
- Почтовые уведомления родителям обслуживаются CRM и этим изменением не затрагиваются.

## Дополнительные проверки

- **Connectivity diagnosis** запускается вручную для диагностики сети.
- **Cloud read performance** запускается по понедельникам 08:23 UTC и вручную: 100 чтений каждого из четырёх публичных маршрутов, параллельность 4. Отчёт хранится 35 дней.
- Бюджеты p95/p99: CRM live 1500/3000 мс; ready 2500/5000; Parent health и catalog 3000/5000. Ошибка, недостаточная выборка или превышение порога проваливает проверку.
- Мониторинг не изменяет CRM или родительские данные.

В публичном репозитории расписания GitHub Actions могут отключаться после 60 дней без активности. При эксплуатационной проверке нужно проверять, что workflow активен и его последние запуски свежие.
