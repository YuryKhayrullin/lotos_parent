# Проверка CRM и родительского кабинета

Команда из lotos_parent: npm run test:integration.

Требования: Node.js 22, Docker, соседний репозиторий lotos_crm и production-сборки обоих приложений (npm run build; для CRM npm run build -- --webpack).

Скрипт создаёт отдельный случайно названный контейнер PostgreSQL с tmpfs и по умолчанию без внешней сети. База не публикует порт хоста. После прогона контейнер удаляется. Существующие контейнеры, локальные и облачные базы не изменяются.

Проверяются:

1. Применение всех 14 миграций и повторное migrate deploy.
2. Вход администратора существующим способом.
3. Создание ребёнка вместе с родительским приглашением и повтор операции без дублей.
4. Активация через настоящий HTTP-маршрут Next.js кабинета.
5. Конкурентное использование одного приглашения.
6. Вход родителя и отдельная cookie.
7. Два ребёнка одного родителя без дублирования аккаунта.
8. Запрет чтения чужого ребёнка, изменения ID и неподдерживаемых параметров.
9. Отображение оплат, расписания и посещаемости из CRM.
10. Серверный рендер родительской главной с данными CRM.
11. Отзыв доступа к одному ребёнку с сохранением доступа ко второму.
12. Выход и прекращение действия сессии.
13. Учётная запись тренера с дополнительной ролью родителя.
14. Сохранение пароля сотрудника при выдаче родительского доступа.
15. Изоляция аудиторий сессий даже при переименовании cookies.
16. Блокировка аккаунта и закрытие родительской сессии.
17. Проверка подписи, времени и параметров запросов шлюза.
18. Идемпотентное создание приглашений.
19. Отсутствие чтения новых таблиц через роли anon/authenticated Supabase.

Данные тестов вымышленные и находятся только в одноразовой базе. Они не появляются в пользовательском интерфейсе рабочего приложения.

## Браузер и расширенная регрессия

Из lotos_crm:

- PARENT_BROWSER=1 npm run test:parent:integration — Chromium: активация, вход, все разделы, компьютер/телефон, отзыв доступа через интерфейс администратора.
- PARENT_REGRESSION=1 npm run test:parent:integration — существующие проверки foundation, auth, каталога, расписания, финансов, документов, восстановления и жизненного цикла.
- Флаги можно объединить.

Браузерный режим создаёт отдельную Docker-сеть и публикует только тестовые HTTP-порты 3002 и 3107 на 127.0.0.1. Рабочие порты и контейнеры не останавливаются. Если порт занят, прогон завершится ошибкой. Временные credentials тестов хранятся в закрытом каталоге и удаляются после завершения. Скриншоты — в .artifacts/parent-portal-browser CRM.

Один тест импорта исходного Excel требует Python/openpyxl и не включён в этот PostgreSQL-контейнер. Импорт не изменялся; отдельные существующие проверки импорта запускаются своим штатным окружением.

## Результат проверки 15.10.2026

- Обе production-сборки проходят.
- CRM: 215 модульных/UI-тестов, typecheck, ESLint и Prettier.
- Родительский кабинет: 6 модульных тестов, typecheck и Prettier.
- PostgreSQL-регрессия: 28 foundation + 46 auth + 117 domain-тестов.
- Сквозной прогон: 5 сценариев, включая Chromium и настоящий Next.js API обоих приложений.
- SQL Editor-релиз проверен поверх 12 исходных миграций, затем повторён с проверкой checksum.
- В браузере проверен отзыв доступа администратором: после обновления ребёнок исчезает из кабинета.
- Рабочие Supabase/Vercel и прежняя родительская база в этом прогоне не изменялись.

Для рабочего стенда ещё нужны миграции 013/014, настройки серверного шлюза и публикация обоих приложений. Старый .env.local кабинета с двумя DB URL необходимо заменить настройками API из .env.example.
