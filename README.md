# Lotos Parent

Отдельный кабинет родителя: расписание ребёнка, отметки посещаемости, остаток занятий и история оплат. Основное приложение — lotos_crm; его код и бизнес-таблицы не изменяются.

Стек: Next.js / React / Tailwind / Better Auth / Prisma / PostgreSQL (Supabase) / Vercel.

В приложении нет демонстрационного маршрута и запасных фиктивных карточек. Без настроенных баз и родительской сессии оно закрывается и не подменяет реальные данные примерами.

### Локальная разработка с рабочей CRM

Локально DATABASE_URL должен указывать на отдельную loopback-базу аккаунтов родителей. Для чтения рабочей CRM допускается удалённый CRM_READ_DATABASE_URL только при LOCAL_CRM_READ=1 и только под ролью lotos_parent_reader. Удалённое соединение использует TLS с проверкой сертификата. В staging/production флаг LOCAL_CRM_READ запрещён.

## Подключение живых данных

1. Создать отдельный Supabase-проект для аккаунтов родителей. DATABASE_URL и DIRECT_URL относятся только к нему. Задать APP_ENV, APP_URL и новый BETTER_AUTH_SECRET по .env.example.
2. Применить npm run db:migrate с DIRECT_URL родительской базы. Команда применяет SQL в транзакции, проверяет SHA-256 и сохраняет историю в parent._prisma_migrations. Повторный запуск безопасен; несовпадение контрольной суммы останавливает применение. Миграция откажется выполняться в базе, содержащей CRM clients/lessons.
3. В родительской базе выполнить sql/parent-runtime.sql, отдельно установить пароль роли. DATABASE_URL приложения использует эту роль; DIRECT_URL остаётся только у оператора.
4. В существующей CRM-базе выполнить sql/crm-reader.sql и отдельно установить пароль lotos_parent_reader. Это настройка доступа, без изменения данных и схемы приложения CRM. CRM_READ_DATABASE_URL — её отдельный URL.
5. В облаке подключаться через Supabase Transaction pooler. TLS проверяется; при необходимости указать CA в DATABASE_CA_BASE64 / CRM_DATABASE_CA_BASE64. Секреты никогда не имеют префикса NEXT_PUBLIC.
6. Выполнить npm run env:check. Проверяется отдельная родительская база, существование таблиц и ограниченная роль чтения CRM.
7. Выдать семье доступ через npm run parent:manage -- create. В закрытом окружении оператора задать PARENT_EMAIL, PARENT_NAME, PARENT_PASSWORD (от 12 символов), CRM_CLIENT_ID и OPERATOR_NOTE. Пароли не передавать в аргументах команды и не коммитить. Подтвердить, что родитель вправе видеть этого ребёнка.
8. Для второго ребёнка использовать link; для отзыва связи — revoke; для отключения аккаунта — disable; для нового пароля — password. Эти операции затрагивают только родительскую базу. Смена пароля и отключение удаляют сессии.
9. Создать отдельный Vercel-проект с Root Directory lotos_parent, Node.js 22, npm ci / npm run build. Указать APP_ENV=staging или production, HTTPS APP_URL, значения двух серверных подключений. DIRECT_URL не нужен серверу приложения; миграции выполнять отдельно.

До этих настроек живое чтение CRM недоступно. Никакие реальные cloud-миграции или деплой при создании проекта не выполнены.

## Проверки

- npm run typecheck
- npm test
- npm run build
- npm run test:integration (Docker с PostgreSQL 17 и установленный Chromium Playwright)
- npm run test:contract (одноразовая база со всеми 12 реальными миграциями lotos_crm)
- PARENT_TEST_SKIP_BROWSER=1 npm run test:integration (HTTP/БД/права без браузера, если Chromium недоступен)

Интеграционный прогон создаёт одноразовый контейнер и две тестовые базы, не использует рабочую CRM. Проверяет миграцию и контрольную сумму, вход, две карточки одной семьи, чужие ID, отзыв доступа, продление сессии, обновления данных, ограниченные права SQL, пагинацию оплат, создание и отключение аккаунта оператором, UI на компьютере/телефоне и ошибку загрузки. Chromium устанавливается командой npx playwright install chromium при необходимости.

Архитектура и источники данных: docs/ARCHITECTURE.md. Маршруты, состояние и устройство интерфейса: docs/FRONTEND_ARCHITECTURE.md.
