# Lotos Parent

Кабинет родителя: расписание ребёнка, посещаемость, остаток занятий и история оплат.

## Архитектура

Два Next.js-приложения, единый основной бэкенд lotos_crm, одна база Supabase PostgreSQL и одна схема public.

- lotos_crm владеет бизнес-данными, общими аккаунтами Better Auth и миграциями.
- lotos_parent содержит интерфейс и серверный шлюз к родительским API CRM.
- В lotos_parent нет подключения к PostgreSQL и отдельной базы аккаунтов.
- Сервер CRM проверяет сессию, роль parent и активный parent_child_links при каждом запросе.
- Родительские сессии имеют отдельную аудиторию parent и отдельные cookies.
- Секрет шлюза находится только на серверах; запросы подписаны с учётом метода, пути, тела, cookie, времени и IP.
- Демонстрационных карточек и подмены ошибок фиктивными данными нет.

## Локальный запуск

Нужен Node.js 22.23.2–22.x. Проект в WSL запускайте средствами Linux.

1. В lotos_crm примените миграции по 016 включительно к выбранной локальной базе.
2. Укажите в окружении CRM PARENT_APP_URL=http://localhost:3100 и PARENT_GATEWAY_SECRET: случайные 64 шестнадцатеричных символа.
3. Создайте .env.local кабинета по .env.example. CRM_API_URL должен соответствовать APP_URL CRM. CRM_GATEWAY_SECRET должен совпадать с PARENT_GATEWAY_SECRET CRM.
4. Запустите CRM через npm run dev:postgres.
5. В lotos_parent выполните npm ci и npm run dev.
6. npm run env:check проверит доступность CRM и совпадение настройки шлюза.

Для локального обращения к удалённой CRM требуется LOCAL_CRM_API=1 и уже обновлённый CRM-бэкенд. Соединение с удалённым API выполняется по HTTPS.

Если локальная сеть использует настроенный HTTP_PROXY/HTTPS_PROXY, запускайте Node с учётом прокси: NODE_USE_ENV_PROXY=1 npm run env:check и NODE_USE_ENV_PROXY=1 npm run dev. На текущем стенде это устраняет таймаут локального обращения к CRM; настройки Vercel от этого не меняются.

## Выдача доступа

1. Администратор открывает карточку ребёнка в CRM.
2. В блоке «Кабинет родителя» указывает email и подтверждает право доступа.
3. Новому родителю выдаётся одноразовая ссылка активации на 48 часов. Передайте её родителю лично. Отправка email реализована в CRM и включается после настройки SMTP. До подключения ящика доступна ручная передача ссылки.
4. Родитель открывает ссылку, задаёт пароль от 12 символов и сразу попадает в кабинет. Если сессию временно не удалось создать, активация сохраняется: доступен обычный вход с email и установленным паролем.
5. Для второго ребёнка используется тот же email. После подтверждения администратора ребёнок появляется в существующем кабинете.
6. Существующий активный аккаунт сотрудника получает дополнительную роль parent. Его пароль не меняется.
7. «Отозвать доступ» закрывает доступ к конкретному ребёнку и отменяет неиспользованные приглашения.

При создании нового клиента можно сразу выбрать «Создать доступ родителю». Ребёнок, связь и приглашение сохраняются в одной транзакции. Контакт сам по себе автоматически не предоставляет доступ.

## Публикация

1. Сначала примените миграции CRM по 016 включительно.
2. Настройте PARENT_APP_URL и новый PARENT_GATEWAY_SECRET в CRM.
3. Обновите CRM.
4. В Vercel-проекте lotos_parent задайте APP_ENV, APP_URL, CRM_API_URL и CRM_GATEWAY_SECRET.
5. Выполните npm run build и опубликуйте lotos_parent.
6. Проверьте /api/health, приглашение, вход, данные и отзыв доступа.

Старые DATABASE_URL, CRM_READ_DATABASE_URL, DIRECT_URL и BETTER_AUTH_SECRET родительскому приложению больше не нужны. Старую отдельную базу не удаляйте, пока не проверен перенос необходимых аккаунтов и связей.

## Проверки

- npm run typecheck
- npm test
- npm run build
- npm run env:check — проверка выбранного живого подключения
- npm run test:integration — изолированный сквозной прогон в соседнем lotos_crm

Интеграционный прогон требует расположить репозитории рядом, собрать оба приложения и иметь Docker. Создаётся случайный одноразовый контейнер PostgreSQL без внешней сети и публикации порта базы. Рабочие базы не используются.

Подробнее: docs/ARCHITECTURE.md и docs/CRM_PARENT_INTEGRATION_TEST.md.

## Документы и cookies

Открытые `/legal/privacy`, `/legal/cookies`, `/legal/consent`, `/legal/terms` работают без входа и CRM. Сейчас это явно обозначенные проекты; реквизиты и тексты ещё не утверждены, юридическое согласие не собирается. При входе/активации/восстановлении есть ссылки. Cookie-уведомление описывает необходимый сеанс и хранит только дату своего закрытия до 180 дней; это не согласие на обработку ПД. Настройки можно открыть повторно. Внешняя карта загружается отдельным действием.

Порядок утверждения и внедрения серверного журнала: [анализ конфиденциальности](../lotos_crm/docs/PRIVACY_REVIEW.md). Публикация требует решения оператора по реквизитам, основаниям, срокам и размещению данных; наличие страниц не является юридическим заключением о соответствии системы.
